# NexusRecon Report File Index

Every campaign writes its output to:

```
campaigns/<client>/<engagement_id>/<campaign_id>/reports/
```

`ReportEngine.generate_all(state)` (in `nexusrecon/reports/engine.py`) produces
these deliverables. Files marked *conditional* only appear when their data or an
optional dependency is present.

---

## Report Files

| File | Format | Contents |
|------|--------|----------|
| `master_report.md` | Markdown | **The cohesive narrative deliverable.** Single document combining snapshot, run-health, executive brief, top threads, conditional attack-surface sections, evidence & provenance, recommendations, and an appendix linking the other reports. The file an operator hands a client when they want one. |
| `master_report.obsidian.md` | Markdown | Obsidian-flavored variant of the master report (wikilinks). *Conditional:* only with `--obsidian`. |
| `executive_summary.md` | Markdown | 1-page summary: overview counts, key findings (first 10), top threads, and the risk-analyst assessment. |
| `full_report.md` | Markdown | Complete findings with methodology, per-finding detail, and MITRE mapping. |
| `top_threads.md` / `top_threads.json` | Markdown / JSON | Top-10 ranked attack threads (score + category + rationale). |
| `asset_inventory.md` / `.json` / `.csv` | Markdown / JSON / CSV | All discovered subdomains, emails, IPs, cloud assets. |
| `phishing_package.md` | Markdown | Target emails, pretext hooks, DMARC gaps, per-employee bundles. |
| `cloud_posture.md` | Markdown | M365 federation, public S3/GCS buckets, cloud exposure. |
| `attack_surface.md` | Markdown | Likelihood x impact matrix, PRE-ATT&CK mapped. |
| `vulnerability_correlation.md` | Markdown | CVE/KEV findings matched to fingerprinted technologies. |
| `people_identity_map.md` | Markdown | Org-chart inference, executive targets, HUMINT leads. |
| `vendor_supply_chain.md` | Markdown | Third-party libraries, CDN providers, CI/CD exposure. |
| `credential_exposure_paths.md` / `credential_punch_list.json` | Markdown / JSON | Personal-identity-to-corporate credential punch list (from phase 2.5). |
| `spear_phishing_intelligence.md` / `pretext_candidates.json` | Markdown / JSON | Per-target spear-phish dossiers and scored pretext candidates (from phase 7.7). |
| `harvested_credentials.md` / `.json` | Markdown / JSON | Exposed credentials with masked values, source URLs, next steps. |
| `entity_graph.html` | HTML | Interactive pyvis view of the living entity graph. |
| `jira_tracker.csv` | CSV | Findings as Jira-importable rows. |
| `executive_briefing.pptx` | PPTX | Executive slide deck. |
| `report.pdf` | PDF | Full report as PDF. *Conditional:* requires the `[pdf]` extra (`weasyprint`); otherwise an HTML fallback `report.html` is written instead. |
| `findings.json` | JSON | All `Finding` objects with severity, confidence, MITRE, provenance. |
| `campaign_meta.json` | JSON | Campaign ID, scope hash, engagement metadata, timestamps. |

Every markdown deliverable carries a scope-hash + tool-version footer so a
delivered file is traceable to its engagement and build.

## Key Files Explained

### `master_report.md`

The single cohesive narrative report. Structure (sections appear only when they
have content unless marked *always*):

1. **Snapshot**: campaign id, scope hash, findings totals, costs (*always*).
1a. **Run Health**: tool-outcome tally, degraded capabilities, and the analysis
    engine (live model vs MockLLM) provenance, rendered when `state['run_health']`
    is present.
2. **Executive Brief**: 200-400 words of LLM-synthesized prose (*always*).
3. **Top Threads to Pull**: the content of `top_threads.md` embedded inline.
4. **Attack Surface at a Glance**: Identity / Cloud / Code & Secrets / Network
   subsections, each shown only when its state is populated.
5. **Identified Personas**: only if any emails were harvested.
6. **Vulnerability Correlation**: only if enriched CVEs or nuclei findings.
7. **Harvested Credentials**: only if credential records exist.
8. **Pretext & HUMINT**: only if pretext intel was collected.
9. **Evidence & Provenance**: scope hash, audit chain, cost ledger (*always*).
10. **Recommendations**: 5-10 prioritized actions (*always*).
11. **Appendix: Deeper Reading**: links to whichever other reports exist (*always*).

Generated by the `master_reporter` agent (one LLM call per campaign, typical
cost < $1.00), which is in `_SKIP_FINDINGS_JSON_AGENTS` so its output is pure
markdown.

### `executive_summary.md` and `full_report.md`

Both open with an overview and render findings. When no LLM key is configured
and the deterministic **MockLLM** fallback produced the analysis, both reports
open with a blunt "MOCK ANALYSIS: templated, not reasoned" banner and prefix
each mock finding with `[MOCK]` plus a "Provenance: MockLLM" line, so templated
output is never mistaken for reasoning. The executive summary lists the first 10
findings (all severities), the top threads, and the risk-analyst assessment.

### `top_threads.md`

Each thread has:
- `score`: `(cvss/10) x max(epss, 0.05)`, then `x3.0` if KEV-listed, `x2.5` if a
  Metasploit module exists (else `x2.0` if a public PoC exists), and `x1.3` if a
  nuclei template exists.
- `category`: one of `cve`, `bucket`, `secret`, `breach`, `exposure`, `pretext`,
  or `harvested_credential`.
- `title`, `description`, `affected_assets`, `suggested_next_steps`.

Header: **`# Top 10 Threads to Pull`**

### `harvested_credentials.md`

**Sensitive, treat as Secret.** Contains credentials extracted from exposed
config/`.env` files and public repos. Values are masked (e.g., `AKIA***KE`) and
hashed (SHA-256); the raw credential is never written to disk. The file is
*always* generated (on an empty run it states no credentials were harvested);
the "real credentials, rotate before sharing" warning banner appears only when
credentials are present.

### `findings.json`

Machine-readable array of `Finding` objects (dumped from `state['findings']`):

```json
[
  {
    "finding_id": "3f2b...uuid",
    "title": "Exposed AWS credentials in .env file",
    "severity": "critical",
    "confidence": 0.95,
    "category": "credential_leak",
    "description": "...",
    "affected_assets": ["example.com"],
    "source": "gitleaks",
    "source_url": "https://example.com/.env",
    "raw_evidence_hash": "sha256:...",
    "evidence_integrity": "unverified",
    "mitre_techniques": ["T1552.001"],
    "provenance": "llm"
  }
]
```

`provenance` is `mock` for MockLLM findings, `llm` otherwise. `evidence_integrity`
is `unverified` for agent findings (the hash digests the finding text, not an
independent tool artifact).

## Return Value of `generate_all()`

`ReportEngine.generate_all(state)` returns a `dict[str, str]` mapping report key
to absolute file path. Keys are the report-path names (e.g. `pdf_report`,
`executive_summary`), which differ from the file names above. A report is not
mapped to `None`: when `weasyprint` is missing, `pdf_report` points at the
`report.html` fallback; when `python-pptx` is missing, `pptx_report` is an empty
string.

```python
paths = engine.generate_all(state)
# {
#   "executive_summary": "/path/to/reports/executive_summary.md",
#   "harvested_credentials": "/path/to/reports/harvested_credentials.md",
#   "pdf_report": "/path/to/reports/report.html",   # weasyprint absent -> HTML fallback
#   ...
# }
```

## Customising Reports

Reports are generated by pure Python string templating in
`nexusrecon/reports/engine.py`. To modify a report's format:

1. Find the private method (e.g., `_top_threads_to_pull()`).
2. Edit the `lines` list; it is plain Python, no template language needed.
3. Run `nexusrecon smoke` to verify the output format is still valid.
